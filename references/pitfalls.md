## Chrome 远程调试拒绝启动

**症状**：`--remote-debugging-port` 启动后端口不通，或直接退出。

**原因**：Chrome 136+ 出于安全考虑（防 cookie 窃取），拒绝在**默认用户数据目录**上开远程调试。

**解法**：必须指定独立的 `--user-data-dir`：

```bash
Chrome --remote-debugging-port=9222 --user-data-dir=/path/to/独立目录
```

代价：这个 profile 是全新的，登录态要重新建立一次。建好之后就一直复用。

在 macOS 上，如果系统把启动请求交给已有 Chrome 实例，可使用 `open -na "Google Chrome" --args ...` 强制建立独立实例。窗口出现后仍要探测调试端口和浏览器版本，不能只凭肉眼判断启动成功。

## 用户数据目录被占用

**症状**：启动 Chrome 时输出「正在现有的浏览器会话中打开」然后进程立刻退出；脚本报 `TargetClosedError` 或连接超时。

**原因**：同一个 `user-data-dir` 同时只能被一个 Chrome 实例持有。上一个实例没退干净（或者你手工开了个窗口用同一目录），新实例起不来。

**解法**：

```bash
pkill -9 -f "user-data-dir=/path/to/目录"
sleep 4
rm -f /path/to/目录/Singleton*      # SingletonLock / SingletonSocket / SingletonCookie
```

**特别注意**：人工开窗口过验证码之后，要**完全退出 Chrome（⌘Q）**再跑脚本，只关窗口不算退出。

## 多个任务抢同一个配置目录

**症状**：明明单独跑好好的，一挂后台循环就 `TargetClosedError`，而且"连续几轮零产出"。

**原因**：同时挂了自动循环脚本 + 手工直接跑，两者抢同一个 profile；或者上一轮循环的清理动作把新一轮的浏览器杀了。

**解法**：
- 循环脚本的轮间清理要彻底（`pkill -9` + 删 Singleton），且**只在自己那一轮结束后做**
- 不要同时跑两个用同一 profile 的任务
- 不同用途用不同 profile（搜索引擎一个、政务站一个、商业平台一个）

**诊断技巧**：区分"真风控"和"启动失败"——真风控日志里有验证页标题（如"百度安全验证"），启动失败是 `TargetClosedError`。看到后者别去等风控解除，是白等。

## Playwright 连不上 CDP

**症状**：`connect_over_cdp` 报 `Protocol error (Browser.setDownloadBehavior): Browser context management is not supported`。

**原因**：Playwright 版本与 Chrome 版本的协议不匹配。

**优先解法**：如果当前 Playwright 提供兼容参数，跳过连接默认项：

```python
browser = p.chromium.connect_over_cdp(cdp_url, no_defaults=True)
```

这仍可读取现有标签、填表并通过 `Page.printToPDF` 打印。若所用 Playwright 不支持
`no_defaults`，再考虑升级/对齐版本，或绕过 Playwright 直接用裸 CDP
（websocket + JSON-RPC）：

```python
import json, time, urllib.request, urllib.parse, websocket

BASE = 'http://127.0.0.1:9222'
tab = json.load(urllib.request.urlopen(urllib.request.Request(
    f'{BASE}/json/new?{urllib.parse.quote(url, safe="")}', method='PUT')))
ws = websocket.create_connection(tab['webSocketDebuggerUrl'], timeout=40,
                                 suppress_origin=True)   # 关键！

_id = [0]
def cdp(method, params=None, timeout=30):
    _id[0] += 1; i = _id[0]
    ws.send(json.dumps({'id': i, 'method': method, 'params': params or {}}))
    end = time.time() + timeout
    while time.time() < end:
        msg = json.loads(ws.recv())
        if msg.get('id') == i:
            return msg.get('result', {})
```

**`suppress_origin=True` 是必须的**，否则 Chrome 返回 `403 Rejected an incoming WebSocket connection from ... origin`。

浏览器自动升级后，应先跑一个主体、一个页面的冒烟测试，覆盖连接、导航、打印和下载行为。不要把修改已安装 Playwright 驱动文件作为常规解法；若临时修补不可避免，必须固定版本、保留补丁并在交付说明中记录。

## 无头 vs 有头的风控差异

实测（百度，同样的冷却参数）：

| 模式 | 单轮完成组数 |
|---|---|
| 有头 + 持久化 profile | ~14 |
| 无头 | ~8 |

**有头明显更抗风控**，代价是抢前台焦点、打断人的操作。

**折中方案**：人过验证用有头，批量打印用无头**复用同一个 profile 的 cookie**：

```python
ctx = p.chromium.launch_persistent_context(
    PROF, headless=True, channel='chrome',
    args=['--disable-blink-features=AutomationControlled', '--no-first-run'],
    user_agent=UA, viewport={'width':1440,'height':900},
    locale='zh-CN', timezone_id='Asia/Shanghai')
ctx.add_init_script("Object.defineProperty(navigator,'webdriver',{get:()=>undefined})")
```

## 后台任务被清理

**症状**：后台跑的批量任务日志是空的、台账没增长，进程也没了。

**常见原因**：
1. 用了 `nohup ... &` 但父进程退出时子进程被回收
2. 命令写成 `cmd & echo started`，工具只跟踪了 `echo`，真正的 python 成了孤儿被清理

**解法**：让任务管理器直接跟踪 python 本体，不要加 `&`：

```bash
python3 -u runner.py          # -u 关闭输出缓冲，能实时看到进度
```

`-u` 很重要：不加的话 stdout 被缓冲，日志文件长时间是空的，会误以为脚本挂了。

## 台账并发写入竞态

**症状**：两个进程分别跑不同渠道，跑完发现台账里只有一个渠道的记录。

**原因**：两边都是"读整个 JSON → 改 → 整体覆写"，后写的把先写的冲掉了。

**解法**（任选）：
- 每个渠道/引擎一个独立台账文件：`进度_百度.json`、`进度_必应.json`
- 或从磁盘文件名反向重建台账（文件名里带够信息就行）

## 证书错误导致打不开

**症状**：`net::ERR_CERT_COMMON_NAME_INVALID`、`ERR_SSL_VERSION_OR_CIPHER_MISMATCH`。政务站配置不规范时常见。

**解法**：

```python
ctx = p.chromium.launch_persistent_context(
    PROF, ignore_https_errors=True,
    args=['--ignore-certificate-errors', ...])
```

留痕件本身不受影响——URL 和内容照常记录。

## 命令行开关漏用

**症状**：台账显示"全部完成"，实际有一整类对象从来没被查过。

**真实案例**：脚本里自然人清单藏在 `--persons` 开关后面，历史上所有批次都没加这个参数——结果 13 个自然人在十几个渠道下**从未被检索过**，而台账看起来是满的。

**教训**：
- 带条件开关的脚本，在 `--help`/文档里写清楚**不加会漏什么**
- 定期做**覆盖率交叉核对**：对象 × 渠道的笛卡尔积 vs 台账实际记录，缺什么一目了然
- 不要只信台账数字，要信"每个应该有的组合都在"

```python
# 覆盖率自查骨架
for obj in ALL_OBJECTS:
    for ch in APPLICABLE_CHANNELS(obj):
        if f'{obj}|{ch}' not in done:
            print(f'缺: {obj} × {ch}')
```

## 正则漏字导致统计长期错误

**真实案例**：计数正则写的是 `共\s*([\d,]+)\s*篇`，但页面实际是"共**检索到** 92 篇"——正则从没匹配上，17 项的计数字段长期显示"?"，没人发现。

**教训**：
- 正则写完要拿**真实页面文本**验证一遍，别凭印象写
- 统计字段出现异常值（全是 `?`、全是同一个数）就是信号，别放过
- 修完之后可以**从已存档的 PDF 反推**修正历史数据，不用重爬

另一个变体：用"某关键词出现次数"估算结果条数，但页面上有个固定按钮也含这个词（如"批量收藏"含"收藏"），导致 0 结果时也报 1 条。**估算逻辑要用页面上唯一、明确的计数文本**，别用可能重复出现的词。

## 同 placeholder 的多个输入框，`.first` 选中了不可见的那个

**症状**：`locator.fill()` 超时 30 秒报 `Timeout ... waiting for locator(...)`，
但截图上那个输入框明明就在页面中间，肉眼可见。

**原因**：SPA 组件库（Element UI 之类）常把同一个搜索框渲染成多份——折叠态一份、
展开态一份、移动端一份，`placeholder` 完全相同。实测巨潮资讯网检索页有 3 个
`input.el-input__inner[placeholder="代码/简称/拼音/关键字"]`，**第 0 个不可见**。
Playwright 的 `.first` 按 DOM 顺序取，正好取中那个隐藏的。

**解法**：永远遍历取第一个可见且可用的，不要用 `.first`：

```python
def first_visible(pg, sel):
    loc = pg.locator(sel)
    for i in range(min(loc.count(), 8)):
        c = loc.nth(i)
        try:
            if c.is_visible() and c.is_enabled():
                return c
        except Exception:
            continue
    return None
```

**更要紧的是**：这类站点即使填对了框，也可能因为前端状态没同步而搜的是空词。
巨潮在填框回车后仍返回"包含""关键词的搜索结果 共 2511 条"——注意引号中间是空的，
2511 是全库条数。**看到计数异常大、且计数行里检索词位置为空，就是检索没生效**，
不能落盘。这种站在验证通过前应整站停用，而不是先存着以后再说。

## 裸关键词误伤正常结果页

**真实案例**：专利审查信息结果页右上角有用户/登录导航，脚本因为正文出现
“登录”二字而拒绝打印，虽然下方已经有一条正式结果。

**教训**：

- 错误页规则要匹配明确语句，如“请先登录”“登录后方可”“扫码登录”；
- 标题规则应匹配标题形态，如标题仅为“用户登录”，不要在整页查裸词；
- 错误/认证判断与结果计数同时出现时，先确认该语句是不是导航栏；
- 词表改动要拿真实的有效页和无效页各测一次。

## 标签页身份漂移

**症状**：脚本声称进入了某查询渠道，浏览器显示的却是上一个渠道；PDF 文件名和
正文类别不一致。

**原因**：按“当前页”“最后一个页”或域名模糊匹配复用了旧标签；新页面短暂
`about:blank` 时又错误退回旧页。

**解法**：

- 点击前记录已有 pages，捕获本次新增 page；
- 等待新 page 离开 `about:blank`；
- 任务从创建 page 到打印一直持有同一个引用；
- 打印前校验精确 URL、栏目标题和当前检索条件；
- 每项完成后只关闭本项创建的标签，不批量关闭不明来源的页面。

## 认证失效另开标签页

**症状**：原结果页仍停留在可见内容，但浏览器上下文中新开了登录页、`noauth` 页或验证码页；只检查当前标签页的脚本继续打印旧内容。

**解法**：

- 在查询、翻页和打印前后扫描上下文中的全部页面；
- 同时检查 URL、标题、正文错误词和新增标签页；
- 出现登录、`noauth`、验证码、访问受限或账号封禁信号时立即停止整批；
- 由人工重新认证、申诉或确认后从台账断点恢复；
- 不通过轮换账号、绕过验证码等方式规避站点控制。

## 中间分页为空

**症状**：首页显示总量大于零，站内第 N 页返回空列表或“0 条”，重新发起查询后第 N+1 页又可能正常。

**风险**：把这一状态当成“该主体无记录”，或用后页内容覆盖空页，都会歪曲网站实际返回状态。

**解法**：

- 以首页总量作为本次查询的基准值；
- 第 N 页标记为 `pagination_anomaly`，保留实际空白输出；
- 从新的查询状态直接探测相邻后页，避免沿用可能损坏的分页状态；
- 空页和相邻验证页进入异常材料组，不计入“无结果”；
- 同一主体的全部分页材料验证完成后再原子归档。

## 访问节奏与风控停止

**症状**：出现访问频繁、访问受限、验证码、认证失效或账号封禁；连续重试使风险进一步恶化。

**解法**：

- 把单主体间隔、每批数量、批间休息和最大重试次数做成配置；
- 普通网络抖动可有限重试，认证或风控信号不得重试当前动作；
- 风控信号触发整批停止，保留最后成功序号和现场信息；
- 恢复后从已验证台账断点继续，不依赖目录中“看起来存在”的文件；
- 速度设置服从站点条款、账号安全和项目时限，不把单次未触发限制视为安全阈值。

## 归一化文本不能拿来做分级判定

做"两次加载是不是同一个页面"的相似度比对时，要把时间戳、浏览量、验证码位这类
每次都变的数字抹掉，否则同一个页面自己跟自己都不相等。常见写法：

```python
def norm(t):
    t = re.sub(r"\s+", "", t or "")
    return re.sub(r"\d{4,}", "#", t)      # 抹掉 4 位以上数字
```

坑在于**把这份文本又拿去做结果分级**。分级要靠「共 N 条」里的 N，而 N 一旦到四位
就被抹成了 `#`。实测 `www.harbin.gov.cn` 的对照页写的是「政策文件相关结果 1234 条」，
归一化后变成「相关结果#条」，计数正则再也匹配不到——一个明摆着的分词型站点被
错判成「待定」，而"待定"的处置是放行去做相似度比对，等于漏掉了一个会产出假命中的站。

**归一化是为相似度服务的，不是通用清洗**。两个用途存两份文本：

```python
def flat(t):                      # 只去空白，数字全留 —— 给分级用
    return re.sub(r"\s+", "", t or "")

def norm(t):                      # 再抹长数字 —— 只给相似度用
    return re.sub(r"\d{4,}", "#", flat(t))
```

同类的坑：`bad_page_reason` 曾在**正文**里搜 403/412/429，而一条新闻链接的哈希
`…bbdc429dad33…` 里含 429，两份正常的克拉玛依市政府检索结果页被静默扔进隔离区。
状态码只在标题/URL 里认。

共同的教训：**为 A 目的做的文本处理，不要顺手拿去喂 B 判定**。清洗永远是有损的，
损掉的恰好可能是另一个判定赖以成立的那一位。

## 回显判据：靠关键词表判"这行是不是正文"会误杀

判断"主体名出现的这一行是检索框回显还是真正文条目"，最直觉的写法是列一张正文
特征词表（日期、`政务公开`、`公告`、`下载`、链接……）。实测会误杀：

> 不断输送着绿色动能。运营这座算力中心的新疆某某数字科技有限公司成立于
> 2024年4月，由上市公司某某某与市云…

这行既无日期也无栏目词，却是一条不折不扣的正文命中。16 份待复核件里靠词表判错了 3 份。

改用**残留字数法**：把主体名和导航词从这一行里删掉，看还剩多少个汉字。

```python
residue = re.sub(r"[^\u4e00-\u9fff]", "", ECHO.sub("", line.replace(kw, "")))
if ITEM.search(line) or len(residue) >= 10:   # 还剩 10 个汉字以上 = 有实质内容
    ...
```

导航词表这时只用来**减字**，不再用来下结论；下结论的是"除了主体名之外这行还说了
什么"。改完 16 份里 13 份判为真正文、3 份判为回显，与人工逐份看的结果一致。

## 相似度闸会误杀"最干净的那一类证据"

用「真实主体页 vs 对照页的正文相似度」来识别"检索参数被忽略、站点渲染了首页"，
是个好判据——参数被丢的站，两张页面逐字相同，相似度 1.0000。

但它有个致命的反向误伤：**入口正常、两次都真的查不到记录时，两张空结果页本来
就该高度相似**，只差回显的检索词；页面不回显检索词时，相似度同样是 1.0000。
于是最干净的一类证据（入口可信 + 明确无记录）被当成首页拦掉了。

所以相似度闸必须给"已证明会执行检索"的入口开豁免：

```python
exact = (GRADE.get(tmpl) or {}).get("分级") == "精确型"
if sim >= SIM_HOMEPAGE and not exact and not c.get("对照页明确报空"):
    return None, f"疑首页：与对照页相似度 {sim:.4f}"
```

判据之间是有依赖顺序的：**对照组先证明入口会检索，相似度闸才有资格谈"这页是不是
首页"**。反过来用，就会把结论最明确的证据丢掉。

实测代价：七台河市与茄子河区两个入口（覆盖 24 条矩阵行）被误拦，而它们的对照页
明明白白写着「搜索结果页 相关结果:0个」。

## 计数正则漏了冒号，把空结果页降级成"待定"

七台河市政府门户的空结果页写的是「相关结果**:**0个」。原正则要求前缀紧挨数字：

```python
re.compile(r"(?:共|找到|检索到|相关结果)(?:约)?([0-9,，]+)(?:条|篇|个|项)")
```

匹配不到 → 判成"既无报空也无计数"的**待定** → 再被相似度闸当首页拦掉。
一处正则少了两个字符，一路把 24 条矩阵行的有效证据丢了。

前缀和数字之间要允许冒号和空格，数字和量词之间也要：

```python
re.compile(r"(?:共|找到|检索到|筛选到|相关结果)[:：\s]*(?:约)?([0-9,，]+)\s*(?:条|篇|个|项)")
```

同一批还补了「为您筛选到 379 条结果」（青岛市统一检索的措辞，不含"找到"）。
**每遇到一种新措辞就把它加进正则，并留一行注释写明哪个站这么写**——
计数措辞的方言比想象的多，靠记忆维护迟早漏。

## 文件名只用域名，同域名的两个部门站会静默互相覆盖

`search.gd.gov.cn/search/all/755016`（深圳市规划和自然资源局）与
`.../755028`（深圳市应急管理局）是**同一域名下的两个部门站点**。文件名里的站点
标识只取 `netloc`，两份证据同名，后者覆盖前者。

后果是**台账 2 条、磁盘 1 份**——除非专门比对两者数量，否则永远发现不了。

站点标识要带上能区分部门的那一段：

```python
pu = urllib.parse.urlparse(tmpl)
seg = [x for x in pu.path.split("/") if x and x not in ("search", "html", "web", "s")]
qid = re.findall(r"(?:siteCode|channelid|channelId|siteId)=([\w-]{4,})", tmpl)
mark = "-".join(([seg[-1][:18]] if seg else []) + ([qid[0][:12]] if qid else []))
```

顺带：每批跑完都该做一次**台账条数 vs 磁盘份数**的对账，这类静默覆盖只有对账能发现。

## 商业网核系统的汇总表「无」≠「无检索结果」

荣大智慧云的网查报告汇总表把「上海证券交易所-全站」一栏对全部 20 家主体标注为
「无」，而对应留痕 PDF 实为 2–20 页、条条有内容——命中的是上市公司自己的年报、
半年报、董事会工作报告里提及该子公司的段落。

该栏的「无」应理解为**无负面/监管类记录**，是供应商的判断结论，不是「检索无结果」。
两者在尽调笔录里性质完全不同。

**接手第三方网核系统的产出时，必须先弄清它每一栏的口径**，并在交付说明里写明
「复核该栏请以留痕 PDF 为准，勿仅凭汇总表下结论」。否则复核人打开一个标着「无」
的条目却翻出 20 页结果，只会认为是我们漏判了。

顺带：核对汇总表与留痕是否一致时，注意上一条——图片式 PDF 抽不出正文，
文本比对会给出「零处不一致」的假结论。

## zxgk（执行信息公开网）页面顶部有固定公布区，判定必须锚定「查询结果」

失信被执行人、终本案件等模块的页面，**顶部是一块与本次查询无关的滚动公布区**
（随机展示全国各地的失信主体，如「嘉兴市某某光电有限公司」「北京某某宠物乐园」）。
真正的「查询条件」和「查询结果」在其下方。

只读 PDF 前若干行会读到公布区，据此判定必然出错——两个方向的事故都发生过：

- 把公布区的无关条目当成命中，误报「该主体有失信记录」
- 反过来，看到顶部一堆无关主体就判「结果与主体无关」，把真命中丢了

判定必须**先定位「查询条件」「查询结果」这两个锚点，再从锚点往下读**；
并核对查询条件区里的名称与统一社会信用代码是否为被查主体。

脚本统计"结果行数"时同理：不锚定就会把公布区的行数一起算进去
（实测报了 10 行，真结果只有 1 行）。

## 纪律写在 SKILL.md 里，不等于实现在脚本里（本文件最该先读的一条）

这个项目里同一种事故发生了三次，每次都不是"没想到"，而是**想到了、写进纪律了、
实现时只落了一部分**：

| 纪律 | 写着什么 | 脚本实际做了什么 | 后果 |
|---|---|---|---|
| 第 1 条 | 检索已执行的判据**三选一**：URL 变化 / 结果区标记 / 空结果措辞 | 只实现了中间那条 | 5 个明明有结果的页面被判「拒绝落盘」 |
| 第 4 条 | 「结果可能开在新标签，**点击前保存已有标签集合**」 | 一直盯着原页 | 原页从头到尾没变化，三条判据全落空，又是一批假阴性 |
| 第 5 条 | 分词型要**打在站点上**，不靠逐页阈值 | 只做了逐页回显计数 | 回显 2 次的页面带着 484 条结果混过阈值 |

所以：**动手写判定逻辑前，先把 SKILL.md 对应那条逐句拆成 checklist，一条一条对着实现。**
三选一就要写三个分支，不能写一个。纪律条文里的「或」「同时」「点击前」都是可执行细节，
不是修辞。

这条事故的共同特征值得记住：**它们全都表现为假阴性**，而假阴性在网核里最危险——
漏检只是没查，假阴性是**把「没查到」写成了「查了没有」**，会直接变成尽调报告里的
一句"经检索未发现"。

## 结果另开一页（target=_blank）：脚本和人看的根本不是同一页

律师看着屏幕说"结果不是出来了吗"，脚本却报"检索疑未执行"——两边都没说谎，
只是**在看不同的标签页**。

实测（2026-09-01）：

| 站点 | 点搜索后 | 原页 |
|---|---|---|
| `fgw.beijing.gov.cn` | 新开 `/so/s?tab=all&siteCode=1100000011` | 纹丝不动 |
| `hrss.sz.gov.cn` | 新开 `/fzlm/cjhzthjs/?keywords=<主体>` | 纹丝不动 |
| `gaj.sh.gov.cn` | 新开 `/shga/vQsAllSearch`（POST 带词） | 纹丝不动 |
| `www.saihan.gov.cn` | 新开 `/so/s?qt=`（qt 被 JS 抹空） | 纹丝不动 |

处置：触发**前**记下 `{id(p) for p in ctx.pages}`，触发后取差集；新页要
`wait_for_load_state` 等到真实 URL（新标签常先是 `about:blank`）；多个新页时，
按「URL 含检索词 > URL 含检索路径 > 其他」排序取第一个。判定和打印都切到新页上，
台账里把切换写清楚（`触发方式: enter（结果另开新页 <URL>）`）。收尾时按差集关页，
别把律师自己开的标签页一起关了。

## 打印时机：「正文不再变化」≠「已加载」

`hrss.sz.gov.cn` 实测：触发后第 0~9 秒，正文稳定停在 **326 字**的页头页脚空壳；
第 14 秒才由 `search.gd.gov.cn` 的 jsonp 异步回填成 **4237 字**的结果页。

拿「正文长度不再变化」当加载完成的信号，会在第 3 秒收工——**空壳自己就很稳定**。
于是打印出一张什么结果都没有的页，台账里还写着「未见结果」。

正确做法是等**阳性信号**，不等"不动了"：
- 出现结果区标记 / 计数行 / 明确空结果措辞（词表见下一条）
- 或正文相对触发瞬间**明显长出来**（实测阈值 `> base*1.5 + 200` 够用）
- 都等不到就按超时收，并把「等满 N 秒仍无结果区」**如实写进台账**，不要静默放行

`settle()` 的返回值要带上依据（"结果区已回填（正文 326→4236 字，等待 6 秒）"），
这行字本身就是复核人判断这份 PDF 可不可信的依据。

## 检索框太窄会裁掉检索词，两页取证的第 1 页当场作废

赛罕区 `#qt` 框宽只容 13 个字。填入「某某某光电（内蒙古）有限公司」后打印，
PDF 上是「**某**某光电（内蒙古）有限公司」——头一个字被裁在框外。
差一个字就是另一家公司，这份专门用来证明"搜的是谁"的检索条件页也就白做了。
（判据上表现为：合成件里主体名出现 0 次，触发降级逻辑，但降级理由是错的。）

处置：打印前放宽该输入框——`style.width` 放大、`fontSize` 调小、`scrollLeft=0`。
**只改显示，绝不碰 `value`**：把检索词写回框里是伪造站点回显；把本来就在框里的词
露出来不是。这项改动要写进台账（"仅改宽度字号，未改动其值"），并与台账里那条
`qt=<主体全称>` 的真实请求互相印证——两者对不上就说明出了别的问题。

## 闸门只能拦一次：人工放行后，下游不能再独立拦一遍

给人工留了「输入 y 强制落盘」的口子，律师按了 y，结果什么都没落下去——
因为下游的 `archive()` 里又独立跑了一遍同一条判据，它不知道上面已经放行过，
照样驳回，条目进了"需人工"清单。**强制落盘成了摆设，而且是静默失效的**：
终端只显示一行"需人工"，不说是被第二道闸拦的。

处置：放行状态要**作为参数往下传**（`forced=True`），下游据此跳过闸门，
并把「本件由律师现场确认，自动判据未命中」写进台账。判断权可以交给人，
但依据必须留痕——不能让底稿里出现一份"来路不明地通过了"的证据。

推论：任何"人工覆盖"的设计，都要检查从覆盖点到落盘之间还有几道同样的检查。

## 计数正则：动宾之间要允许夹一个短名词

继「漏了冒号」之后的同类事故。上海市公安局写的是「找到**记录**约 0 条，耗时 0.162 秒」，
正则贴着「找到」写（`找到(?:约)?(\d+)条`）匹配不上，于是一张**回显了主体全称、
明写 0 条**的标准无记录页，被判成「未出现可复核计数、需人工确认」。

统一写成 `(?:找到|检索到|查询到|搜索到)[^0-9]{0,6}?(?:约)?([0-9,，]+)\s*(?:条|篇|个|项)`。
每遇到一种新措辞，补进 `evidence_core.COUNT_PATTERNS` 并跑一遍回归——
这个正则是"无记录"结论的唯一来源，漏一种措辞就少一批可以直接结案的证据。

## 词表要和判定层共用一份，否则台账会自相矛盾

赛罕区那份 PDF：判定层认得「未能搜到」（在 `EMPTY_PHRASES` 里），
脚本自己的 `MARK` 词表没收录。结果台账一边写「结果计数明确为空」，
一边写「等满 25 秒仍无结果区标记」——**同一份证据两句话打架**。

复核人看到这种自相矛盾，不会去追是哪一层的词表漏了，只会不信这份证据。
处置：`MARK = tuple(dict.fromkeys(自有词 + tuple(EMPTY_PHRASES)))`，
从判定层导入，不要各写各的。

## HTTP 探针报的「403 / 502 站点不可用」有一半是假的，必须用真实浏览器复验

政府站普遍对非浏览器请求直接拒。拿 requests/curl 探针的结论去写《查询说明》里的
「该站点不可访问」，等于把**我们没用对工具**写成**客观不能查**。

2026-09-01 用常驻 Chrome 逐个复验，一批「不可用」当场翻案：

| 站点 | 探针结论 | 浏览器实测 | 影响 |
|---|---|---|---|
| `www.chinabx.gov.cn` 哈尔滨宾县 | 502 Bad Gateway | **200，首页有检索框** | 救回 12 行 |
| `ajj.qingdao.gov.cn` 青岛应急 | 403 Forbidden | **200，`#searchWord`** | 救回 1 行 |
| `mbee.qingdao.gov.cn` 青岛生态环境 | 403 Forbidden | **200，`#searchValue`** | 救回 1 行 |
| `dpc/police/zrzygh.qingdao.gov.cn` | 403 | 浏览器下**仍 403** | 真不可用，另寻渠道 |
| `www.huhhot.gov.cn` 呼和浩特 | 首页空白 | 云防护「站点不存在，未接入云防护」HTTP 422 | 真挂了，但**各部门子站活着** |

规矩：**任何要写进底稿的「站点不可用」，都必须附真实浏览器下的复验现象**
（HTTP 状态 + 页面原话），而不是探针的一行报错。复验成本是每站十几秒，
换回来的是几十行覆盖，以及一句不会被打脸的结论。

## 市级部门没有独立网站时：用市政府自己的「统一检索 + 范围参数」，别用不限范围的门户检索

很多市的部门只有市门户下的一个信息公开专页，没有独立域名。这时有两条路，
**一条合法一条不合法，区别只在有没有把范围限定住**：

| | 做法 | 是否可用 | 为什么 |
|---|---|---|---|
| ✗ | 拿市门户全站检索交差 | **不可用** | 青岛实测：不带范围参数时结果来源标签清一色「青岛政务网」，它只索引门户自身内容，根本不含该部门站点 |
| ✓ | 市政府统一检索 + 范围参数 | 可用 | 搜的就是该部门站点的内容，且**页头会印出范围标签**，留痕件上可复核 |

实测到的三套范围参数：

- **青岛** `www.qingdao.gov.cn/unionsearch/?searchWord={kw}&sitetype=all&areaId=N`
  areaId 可枚举（14 发改委 / 17 公安局 / 22 自然资源和规划局 / 23 生态环境局 /
  35 应急局 / 39 市场监管局 / 52 公积金中心），页头显示「市公安局」等标签
- **上海** `search.sh.gov.cn/search?siteId=<部门域名>&text={kw}`
  如 `siteId=scjgj.sh.gov.cn`，页头显示「市场监管局」，结果条目来源标注该域名
- **哈尔滨** `www.harbin.gov.cn/so/xxgk/s?qt={kw}`（政府信息公开平台检索）
  结果页带**发文机构分面**（市生态环境局、市工信局…），分面按结果集动态生成、
  没有独立 URL 参数——但分面本身就是证据：某部门不在分面里 = 该部门无相关公开信息

**判断标准很简单：范围有没有印在留痕件上。** 印出来了才叫限定检索，
印不出来就是拿别的内容顶替。

顺带一条：部门信息公开专页「没有检索框」的结论也要复验。哈尔滨那 18 行原本记着
「该页无站内检索框」，实际页面上有 `#ipt`，通向的正是上述信息公开平台检索。

## 复用别的脚本的函数时，要连它依赖的模块级常量一起接管

新 runner 里 `import` 了半自动脚本的 `archive()` 复用判定逻辑，结果跑完显示
「成功 17 项」，而本脚本的留痕目录里**一个文件都没有**——
`archive()` 用的是它自己模块里的 `OUT`/`PENDING` 常量，17 份 PDF 全落进了别人家的目录，
而本脚本的台账指向自己的目录，落盘与台账彻底对不上。

复用函数 ≠ 只复用代码，还继承了它的模块状态。接管写法：

```python
AJ = importlib.util.module_from_spec(spec); spec.loader.exec_module(AJ)
AJ.OUT, AJ.PENDING = OUT, PENDING     # 必须接管，否则落盘落到别人家去
```

**收尾时对一次「台账条数 = 不同文件名数 = 磁盘份数」**，这三个数不相等就有事故：
本轮靠它先后抓出「落错目录」和「同 host 撞名覆盖」两次（台账 24 / 磁盘 20）。

## 触发方式的三个新坑

- **表单可能显式禁用回车。** 内蒙古税务局的检索表单写着
  `onkeydown="if(event.keyCode==13){return false;}"`，填框敲回车永远没反应。
  它是 TRS WAS5，改走 GET 直达即可：`/was5/search?channelid=<id>&searchword={kw}`。
- **检索框可能藏在隐藏的手机版浮层里。** 上海公积金的 `#nn1` 位于
  `<div id="mobile-search-area" style="bottom:-100%">`，选择器能选中、点击必然超时；
  桌面版的同功能框是 `#nn`，触发是同容器内的 `<a onclick="a()">`。
  **按 id 顺序取第一个匹配是危险的**，要先确认它在视口里可点。
- **全角括号会打断某些站的检索。** 呼和浩特几个「智能云搜索」站对
  「某某某光电（内蒙古）有限公司」返回「您访问的页面已撤稿或删除」，
  换成半角括号或去掉括号部分就正常返回结果页。遇到含全角括号的主体名多留一眼。

## 打印页眉页脚是打印器加的，不是页面内容

Chrome 打印的页眉印 `document.title`、页脚印完整网址，**每页都印**。
拿整份 PDF 文本去判「页面未渲染完」，会被页眉里的 title 带偏：

> 内蒙古公安厅检索页正文写着「相关结果约 0 个／很抱歉！未能搜到您想要的内容」，
> 页眉却是「加载中」—— 单页应用从不更新 title。
> 结果一份完好的空结果件被判成半成品，连拒三轮。

判定前先剥掉每页首行和末行：

```python
def _strip_print_furniture(text):
    out = []
    for page in text.split("\f"):
        lines = [x for x in page.splitlines() if x.strip()]
        if len(lines) > 2:
            lines = lines[1:-1]          # 去掉页眉、页脚
        out.append("\n".join(lines))
    return "\n".join(out)
```

页眉页脚里真有异常另有两道关：`grab()` 的标题粗筛、`archive()` 对**实时正文**
的判定。同理，**加载态词表只能扫正文，不能连标题一起扫**。

## 检索词挂在 URL 的井号片段里，前端可能根本不读

内蒙古自治区各厅局站群的检索结果页长这样：

```
http://gat.nmg.gov.cn/nmg_dept_search/#/Door?keywords=<主体名>&siteTag=1
```

检索词在**片段**（`#` 之后）里。片段不发给服务器，要靠前端 JS 自己读。
读不读，站与站不同：

- 首页填框后点按钮跳过去 → 有的站正常按词过滤
- **直接 goto 这个 URL** → 有的站只渲染默认内容

内蒙古公安厅那份就栽在这：URL 上明明挂着检索词，打印出来是**七页首页新闻**，
判定层看 URL 带词就放了行，落盘时标着「无记录」。
**这是最危险的一类假证据：看着像「查了没有」，其实根本没查。**

判据：

1. 结果页 URL 的 path 还是站点根路径（`/` 或空）→ 直接拒。
2. 单页直达件，**正文和页脚网址里都找不到检索词** → 拒。
   注意页脚印的是原始 URL，中文是**百分号编码**的，只找中文会漏判：

   ```python
   seen = (kw_flat in text_flat) or (urllib.parse.quote(kw) in text)
   ```
3. 片段型 URL 要**先证伪再采信**：同一主体名，分别开首页和开片段 URL，
   两者返回不同（首页是新闻列表、片段 URL 是「相关结果约 0 个」）才说明片段被读取。
   证伪过的站列进白名单，没证伪过的一律退回填框 + 两页取证。

## 云节点的 502 网关错误页混在正常页后面

北京法院网检索，存下来 4 页：前 3 页是法院网首页（新闻、法院公告、辖区法院网站群），
第 4 页才是 `Error 502 网关错误 / 云节点 / 源服务器 / 您的IP: …`。
检索请求根本没到源站，前面那几页是缓存的首页。

只看第一页会以为检索成功了。错误词表要收 `网关错误 / 网关超时 /
bad gateway / gateway timeout / 源服务器`。

## 站内文章检索 ≠ 业务数据查询（口径错，比技术错更隐蔽）

信用中国省级子站首页那个框，多数是**站内文章检索**，搜的是「信用动态」
和「政策法规」两个栏目：

> 信用中国（黑龙江）结果页原文：
> 「分类检索：信用动态　政策法规　检索到 相关信息共 0 条，命中点：0」

拿这个 0 条写「未发现该企业负面信息」，是把**没查**写成**查了没有**。
企业信用记录要走另一个入口：首页框上方那排切换里的「**信用信息**」
（另两个是「统一社会信用代码」和「站内文章」），或「企业信用信息查询」专页。

**技术上没有任何报错，页面完好，计数明确 —— 只有读懂页面上那行小字才能发现。**
凡是「某平台的站内搜索」，落盘前都要回答一句：它检索的数据集，
是不是笔录那一行要问的数据集？

## 单页直达件必须能自证「查的是谁」

直达 URL 的证据契约是**页脚那行网址带着检索词**。但有的站结果页
既不回显检索词、URL 又被 JS 改写，单页存下来只是「某次检索得 N 条」。

规则：**填框件一律两页取证**（第 1 页检索框里带词，站点自己渲染的），
直达件才允许单页，且要过上面第 2 条的自证检查。

## 无头模式：可以用，但要对拍

`--headless=new` 与有头**同一个浏览器**，只是没有窗口；老的 `--headless`
是另一套精简实现，打印路径和字体都可能不同。换模式前拿一个已有的有头件
同站同词重跑，逐字比（抹掉时间戳）：

```
有头 280 字 / 无头 280 字 → 完全一致
「未能搜到」「主体名」「页脚网址」 有头=True 无头=True
```

限制：**需要人工过验证码、滑块的站不能用无头**，没人能点。

## 多个 Chrome 并行：端口 + profile 都要隔离

律师在自己的浏览器里干活，脚本别去抢。`capture.py` 认
`WEB_EVIDENCE_PORT` 和 `WEB_EVIDENCE_PROFILE`，两个都改才是真隔离
（只改端口会因为 user-data-dir 被锁而起不来）：

```bash
WEB_EVIDENCE_PORT=9333 WEB_EVIDENCE_PROFILE=/tmp/chrome_9333 \
  python3 capture.py start
```

**注意 `opened_since(ctx, base_ids)` 会关掉快照之后新开的所有页**——
两个脚本连同一个浏览器时会互相关标签页。要并行就换端口，别共用。

## 检索按钮不长得像按钮

内蒙古各厅局站群：**没有 form**，按钮是 `<div class="s-btn" onclick="btnonclick()">`
里面套一张图。`button[type=submit]`、`[class*=search-btn]` 这类选择器一个都匹配不上，
Playwright 的可见性判定也常把它滤掉，只有 JS 直接 `click()` 才动。

兜底顺序要**先按名字全页找、再按位置找**：

```javascript
// ① 挂着 onclick 且名字像检索的，全页找 —— 不依赖位置
const named = [...document.querySelectorAll('[onclick],div,span,a,button,i')]
  .filter(e => /btnonclick|s-btn|search-?btn|sousuo/i
    .test((e.getAttribute('onclick')||'')+(e.className||'')+(e.id||'')));
// ② 找不到再退回「检索框右侧」的位置判据
```

位置判据在这里单独用会失效：打印前 `widen_box()` 把检索框及其外层容器放宽了，
按钮早被挤出「框右侧 140px」的范围。

## 归档撞名：按内容命名，别按来源加后缀

同一主体同一渠道有两份文件时，加 `（本所-国家级）`、`（本所-律师人工）`
这类来源后缀能防覆盖，但**读起来像在给自己留退路，而且没说清两份差在哪**。
律师原话：「把这种防御性表述在命名中去掉」。

分三种情况处理，实测把 240 个带后缀的文件名降到 0：

| 情况 | 处理 |
|---|---|
| 同一主体、**同一条 URL** 跑了两遍（分批跑难免） | 去重，只留一份 |
| 同一部门换了入口跑两遍（URL 不同，问的是同一件事） | 按预设优先级留一份，**优先留人工核过的那份** |
| 商业报告 + 本所自查（是两样东西，都要留） | 按内容命名：`国家税务总局.pdf` / `国家税务总局-网查报告.pdf` |
| 同一域名挂多个部门（范围限定检索） | **读留痕件页首印着的范围标签当名字**：`市级 深圳市应急管理局.pdf` |

## 去重要按覆盖挑，不能按名字挑

上一条的去重差点闯祸。同一条 URL 在「地方」和「地方部门」两批里各跑过一次：

- 「市级 哈尔滨市政府门户」—— 名字好读，台账里**没记覆盖矩阵行**
- 「市级 哈尔滨市松北区 www.harbin.gov.cn」—— 名字难看，**带着 6 行覆盖**

只按名字挑，笔录上那 6 行会当场从「已查」变成「本次未查询」。
正确做法：**覆盖留最全那份，名字取最好读那份**，两样都要。

```python
v.sort(key=lambda x: (-n_rows(x), has_domain(x["渠道"]), len(x["渠道"])))
best = v[0]
best["渠道"] = sorted(v, key=lambda x: (has_domain(x["渠道"]), len(x["渠道"])))[0]["渠道"]
```

还要把**被丢那份的覆盖行并到留下这份头上**：上海是直辖市，
省级药监局和市级药监局是同一个网站同一条 URL，两批分别记了模板第 41 行和第 53 行，
只留一份而不并覆盖，第 53 行就凭空变成「未查询」。

## 渠道名里不能有分号

笔录「留痕载体」那列是用「；」把多个文件名串起来的。渠道名自带分号
（层级写成「市级；区县级」）会让那列读不出边界：
`市级；区县级 青岛市住房公积金管理中心.pdf` 会被读成两个文件名。
清洗时统一换成顿号。

## 等待循环用 pgrep 自查会死锁

```bash
until ! pgrep -f runner.py >/dev/null; do sleep 20; done   # 永远不退出
```

`pgrep -f` 匹配**完整命令行**，而这条等待命令自己的命令行里就含着 `runner.py`，
于是它永远查得到「还有进程在跑」。要么用文件标记，要么排除自身 PID。

## 「站点无检索功能」这句话，最好由人来下

脚本判「首页找不到检索框」，只能说明**通用选择器没匹配上**。
本批里被脚本判成无入口的站，律师人工一看：山东高院、河南高院确实没有；
但内蒙古应急厅有（按钮是个 div）、内蒙古公安厅有（`#wxf_search_new_input`）、
黑龙江几个厅也有（换个协议或域名就开）。

**写进《查询说明》的「站点无检索功能」应当是人确认过的结论**，
脚本给的是线索。同理「站点不可访问」——见上文 HTTP 探针那条。
