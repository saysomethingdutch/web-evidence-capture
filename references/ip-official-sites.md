# 知识产权官网留痕专项

本页记录的是知识产权官网自动化中可复用的技术模式。具体项目应查哪些主体、
哪些权利、是否适用近似查询，仍由项目核查方案决定；不要把某次项目的取舍写成
普遍法律结论。

## 17 个卡点如何归类

项目运行日志中的 17 条卡点不是 17 套不同问题，可归并为 6 类：

| 可复用模式 | 原始条数 | 本质 | 处理方向 |
|---|---:|---|---|
| CNNIC 验证码 / 滑块 | 4 | 人工验证门槛 | 脚本填域名并停住；人工验证后确认结果页，再打印 |
| 中国版权保护中心结果页未确认 | 4 | 多字段检索 + 结果页结构判断 | 同时填登记号和著作权人/软件名；允许人工确认，不凭关键词回显判命中 |
| 中国商标网综合查询入口 | 4 | 多入口同域名 + 标签页混淆 | 每种查询绑定精确 URL 和页面身份标记；新建并锁定本次 page |
| 信用中国知识产权出质选择器歧义 | 1 | 同页有多个相似控件 | 使用栏目容器内的局部选择器；无法唯一定位则转人工 |
| 著作权质押结果结构不稳定 | 2 | 有检索条件但缺少稳定结果标记 | 只做半自动填词；人工确认正式结果区，不能从入口页下结论 |
| ICANN 条款同意 / Lookup 禁用 | 2 | 前置同意状态阻断按钮 | 人工接受条款后复用会话；检查按钮 enabled 和结果 URL |

归类的目的不是减少留痕数量，而是避免为每个对象复制一份几乎相同的特殊代码。
站点模式写在 reference；对象、号码和输出名留在项目清单。

## 先确认“查询维度”，再决定留痕份数

同一权利可能需要多个相互独立的查询维度。例如商标官网至少可能涉及：

- 近似查询：按国际分类和检索要素观察相同、近似标识；
- 综合查询：核对申请/注册号、申请人、类别、期限等基本信息；
- 状态查询：核对流程节点和当前法律状态；
- 公告查询：核对注册、转让、质押等公告事项。

它们不是同一页面的四种叫法。项目要求四种维度时，应分别形成可复核结果，
不能拿综合查询 PDF 代替近似或公告查询。

项目曾验证的入口如下；网站改版时应先手工确认页面标题和字段，再更新配置：

| 查询 | 入口 |
|---|---|
| 商标近似 | `https://wcjs.sbj.cnipa.gov.cn/sistm` |
| 商标综合 | `https://wcjs.sbj.cnipa.gov.cn/sgtmi` |
| 商标状态 | `https://wcjs.sbj.cnipa.gov.cn/stmas` |
| 商标公告 | `https://pub.sbj.cnipa.gov.cn/toas-pub-prod/portalui-pub-prod/brandNotice` |

### 商标入口的关键防错

1. 不复用“当前最像结果页”的旧标签。每项保存创建时的 `Page` 对象，并在打印前
   同时核对 URL、页面标题、选中栏目和当前检索条件。
2. 近似查询至少需要国际分类和检索要素；类似群可能仍要人工选择。脚本只填了
   商标文字，不等于检索条件完整。
3. 英文、图形或组合商标是否能以某种查询方式覆盖，要按官网功能和项目方案判断。
   某次项目选择“不适用”不能变成通用跳过规则。
4. 公告系统可能产生新标签、下载件或短暂 `about:blank`。应等待新页面取得真实 URL，
   不能立即打印空白页，也不能退回旧标签打印。

## 专利：三个官网承担不同证明任务

### 专利检索及分析系统

用于检索公开专利并核对摘要、申请人、发明人和基本法律状态。结果表格往往较宽，
打印前可在站点配置中设置 `"pdf_options": {"landscape": true}`；但横向只是版式
选择，不改变结果页验证。

### 中国及多国专利审查信息查询

项目验证入口：

`https://cpquery.cponline.cnipa.gov.cn/chinesepatent/index`

实务要点：

- 申请号/专利号常需去掉 `ZL`、空格并规范为 `201620825436.9` 形式；
- 页面顶部正常含用户状态和“登录”导航，不能因全文出现“登录”就拒绝打印；
- “共查询到 N 条结果”、案件状态、费用或著录项目是结果信号；
- 列表有结果时也要核对号码和名称，不能只看计数；
- 登录态过期、验证码或明确“请先登录”才属于认证前置页。

### 中国专利公布公告 / 事务查询

项目验证过的事务查询结果位于 `epub.cnipa.gov.cn`。入口跳转可能经历
`about:blank`，并可能在同一站点出现“专利公报查询”和“事务查询”两个不同模块。
脚本应验证当前模块和检索条件，不能仅凭域名相同就归档。

## 软件著作权：必须区分“登记公告”与“权利状态”

中国版权保护中心的登记公告查询在项目运行中出现过以下现象：

- 右侧条件必须填著作权人或软件名称，只有登记号可能返回 0；
- 变更/补充登记公告可能显示登记号和变更后的著作权人，但“软件全称”为空；
- 相同条件短时间内可能一度返回 0、稍后又返回结果；
- 页面会回显检索条件，因此“全文含登记号/著作权人”不能证明结果命中。

稳妥流程：

1. 用登记号作为精确条件；
2. 第二条件优先使用清单中确认的著作权人；必要时再以软件全称交叉查询；
3. 核对结果区中的登记号、公告类型、著作权人和软件全称；
4. 明确的 0 结果也打印留痕，但网站状态异常时重复查询；
5. 结果忽有忽无、名称空白或仅有变更公告时，标为人工核阅，不擅自推断权利不存在。

商业数据库可以作为清单完整性和名称差异的交叉核对来源，但不能在未说明口径的
情况下自动替代官方登记公告。若项目决定采用商业报告，应在核查说明中写明原因、
查询时间和差异处理。

## 域名、备案与条款页

### 工信部 ICP

备案查询的有效证据应同时看见所查域名、备案主体或明确无记录结果。检索框回显域名
不够。滑块或验证码由人工完成，脚本等待结果区后打印。

### CNNIC WHOIS

适合 `.cn` 及中文域名。若出现滑块/验证码，采用“脚本填域名—人工完成验证—回车打印”
的半自动模式。结果页应包含域名、注册者、注册时间等字段，或明确无数据。

### ICANN Lookup

更适合国际通用顶级域名。`.cn` 可能显示没有对应 RDAP server，这本身可以作为该渠道
的结果留痕，但不能据此推断域名未注册；应结合 CNNIC。首次使用可能要求接受条款，
未接受时 Lookup 按钮不可用，应先由人工完成前置同意。

## 什么时候转人工

以下任一情形出现时，不继续“猜选择器”：

- 页面存在多个同名输入框或按钮，无法把控件唯一绑定到目标栏目；
- 已点击搜索，但 URL、栏目或结果区没有出现可复核变化；
- 结果数量非零，但列表与完整权利号/名称对不上；
- 同一条件重复查询结果相互冲突；
- 页面处于验证码、条款同意、登录过期、WAF 或 `about:blank`；
- 官网字段含义不足以支持项目要求的法律结论。

此时自动化仍可以负责填词、置前、打印和归档；法律判断与不稳定交互留给人工。
